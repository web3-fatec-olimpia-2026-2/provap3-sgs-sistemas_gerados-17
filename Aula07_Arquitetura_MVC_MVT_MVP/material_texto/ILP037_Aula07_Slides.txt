===== Página 6 =====
MVC, MVT, MVP
Três nomes, um princípio
O QUE TODAS DIZEM
Separe o dado, a regra e a apresentação. Discordam só em onde cada parte mora e
quem chama quem.
dado regra apresentação
MVC Model Controller View
MVT (Django) Model View Template
MVP Model Presenter View (passiva)
No Django, a "View" é a REGRA (o Controller do MVC). Não decorem as siglas —
reconheçam a separação no código.

===== Página 8 =====
Por que isso importa
Testabilidade é consequência de boa arquitetura
A REGRA QUE SABE O QUE É WEB
...só pode ser testada subindo a web. Testar fica caro. E o que é caro, ninguém faz.
Então a regra fica sem teste.
A REGRA QUE NÃO SABE O QUE É WEB
...é testada direto, num piscar. Testar fica barato. E o que é barato, todo mundo faz. A
regra fica protegida.
Isto é o SRP da Aula 06 em escala de camadas: uma classe, uma responsabilidade -> uma
camada, uma responsabilidade.
Fatec Olímpia 7/14
===== Página 9 =====
Quando NÃO extrair
O antifachada de sempre
SERVICE SÓ QUANDO HÁ REGRA DE VERDADE
Uma view que só lista objetos e renderiza está ótima. Não crie um Service para ela. O
Service se justifica quando há cálculo, decisão, ou orquestração de vários passos.
Extrair Service de view trivial é a mesma sobre-engenharia de sempre. A competência é
decidir se cabe.
Vocês já sabem esse critério: vale para padrão, vale para princípio, vale para arquitetura. Não aplique
porque é "boa prática" — aplique porque o problema pede.
