LAB 1 — SQL na Mão com SQLite (A Culinária do Resort)
No banco de dados do Resort, as informações estão organizadas em tabelas interligadas: a tabela quarto (com id, numero, tipo, diaria) e a
tabela reserva (com id, hospede, quarto_id, dias). O comando SQL indica diretamente ao banco o que buscar e como filtrar.
Cláusula
Função Prática
Exemplo Prático (Tabelas do Resort)
SELECT
Define quais colunas de dados você quer visualizar no
resultado.
SELECT numero, diaria FROM quarto;
FROM
Especifica de qual tabela principal os dados serão
extraídos.
FROM quarto;
WHERE
Aplica uma condição de filtro para selecionar apenas
certas linhas.
WHERE tipo = 'Presidencial';
JOIN
Junta duas tabelas conectadas pelo elo (quarto_id
aponta para id).
SELECT r.hospede, q.numero FROM reserva r JOIN quarto q ON
r.quarto_id = q.id;
Frase-Chave para a Unidade 3: "O ORM gera SQL por baixo."
O ORM (Object-Relational Mapping) do Django funciona como o garçom do Resort: você faz o pedido em Python (ex.:
reserva.quarto.numero) e ele anota em português, mas traduz o pedido em SQL para a cozinha do banco de dados (SQLite). Entender
SQL na mão é saber como a cozinha funciona de verdade!
LAB 2 — Git Além do Commit: Branch e Conflito (A Gestão de Quartos)
 Branch (Linha Paralela): Uma ramificação de trabalho isolada onde você cria novas funcionalidades ou correções sem afetar a versão
estável principal (main).
 Conflito de Merge: NÃO é bug nem erro seu! É o Git sendo honesto e pedindo uma decisão humana quando duas branches alteram a
mesma linha do código de formas diferentes.
Entendendo as Marcas de Conflito no Arquivo:
<<<<<<< HEAD       ← Início do código na branch atual (ex: main / Suíte Luxo)
categoria = 'Suíte Luxo'
=======             ← Divisória central entre as duas propostas de alteração
categoria = 'Suíte Presidencial'
>>>>>>> nova-categoria ← Fim do código vindo da outra branch mesclada
Como Resolver: 1. Abra o arquivo no editor; 2. Escolha o código correto (ou combine ambos); 3. Apague as três linhas marcadoras (<<<,
===, >>>); 4. Salve e execute os comandos de gravação abaixo.
Comando Git
Ação e Função Prática
git checkout -b <nome>
Cria uma nova branch paralela e alterna o trabalho para ela.
git merge <branch>
Junta as alterações da <branch> indicada na sua branch atual.
git add <arquivo>
Prepara o arquivo ajustado (e marca o conflito resolvido como pronto).
git commit -m "msg"
Conclui o salvamento definitivo da fusão no histórico do projeto.

LAB 3 — Ler um Erro no Python em 3 Passos (O Check-out Sem Pânico)
Regra de Ouro do Traceback: Leia a mensagem de erro sempre de BAIXO PARA CIMA!
O meio da mensagem na tela mostra apenas o caminho que o Python percorreu até travar. A causa real do problema está na última linha.
Exemplo Real de Traceback e seus 3 Passos de Leitura:
Traceback (most recent call last):
  File "calculo_diaria.py", line 14, in <module>    ← Passo 2: ONDE (linha 14 de calculo_diaria.py)
    valor_total = diaria_padrao * dias
NameError: name 'diaria_padrao' is not defined     ← Passo 1: O QUÊ e Passo 3: PISTA (NameError)
Passo 1: Última Linha (O QUÊ)
Passo 2: O 'line N' (ONDE)
Passo 3: Tipo da Exceção (PISTA)
Vá direto para o final da tela. A mensagem
diz exatamente qual problema ocorreu na
execução.
Localize o nome do arquivo e o número da
linha exata (ex.: line 14) onde o código
parou.
O nome do erro (ex.: NameError, ValueError)
entrega a pista direta da causa.
