LAB 1 — OBJETOS: CONSTRUINDO A CLASSE DO ZERO
O Conceito: Uma classe funciona como um molde abstrato (projeto) que define o comportamento e os dados de
uma entidade, enquanto um objeto é uma instância concreta gerada em memória a partir desse molde, possuindo
seu próprio estado e dados independentes dos outros objetos.
O Código em Python:
class Hospede: def __init__(self, nome, documento): self.nome = nome # Atributo de instância para
guardar o nome self.documento = documento # Atributo de instância para o documento self.hospedado =
False # Estado inicial: não hospedado def fazer_check_in(self): self.hospedado = True # Método: altera
o estado do objeto específico
Analogia do Resort de Olímpia: Imagine a planta arquitetônica de um quarto padrão do resort. A planta em si existe
apenas uma vez no papel (isso é a classe). Já cada apartamento físico construído no resort (como o Quarto 101 e o
Quarto 102) é um objeto concreto. Se o hóspede do Quarto 101 acende a luz (fazer_check_in), apenas a luz daquele
apartamento acende (o estado do objeto Quarto 101 muda para True); o Quarto 102 permanece intacto no escuro
(False), pois cada objeto carrega seu estado independente!
LAB 2 — ENCAPSULAMENTO: A FECHADURA DE SEGURANÇA
O Conceito: Atributos públicos estão expostos a modificações indevidas (como idades negativas). O
encapsulamento protege os dados internos (usando um sublinhado como _idade por convenção) e expõe uma
interface segura usando decoradores @property e .setter, validando os dados antes de aceitar qualquer alteração de
estado.
O Código em Python:
class Hospede: def __init__(self, nome, documento, idade): self.nome = nome self.documento = documento
self.idade = idade # Ativa o @idade.setter automaticamente! @property def idade(self): return
self._idade # Getter: permite ler a idade de forma segura @idade.setter def idade(self, valor): if
valor < 0: raise ValueError("Idade nao pode ser negativa") self._idade = valor # Setter: valida o valor
antes de gravar
Analogia do Resort de Olímpia: Pense no cofre digital instalado dentro do quarto do resort. O hóspede não tem acesso
direto à fiação ou ao circuito mecânico da fechadura do cofre (isso é o atributo privado _idade). Ele precisa digitar a
senha no teclado externo digital (a interface pública protegida pelo setter). Se o hóspede digita uma senha inválida ou
tenta fazer algo proibido, o sistema rejeita a operação. Um atributo público seria como deixar a porta do cofre aberta e a
fiação exposta; o encapsulamento com @property e setter garante que o dado só seja alterado de forma válida!

LAB 3 — HERANÇA: QUARTOS DA CATEGORIA VIP
O Conceito: A herança permite criar novos tipos mais específicos a partir de classes gerais que já existem,
reaproveitando dados e comportamentos sem duplicar código (relação 'é-um'). A função super() chama o construtor
da classe mãe, herdando os atributos básicos e seus validadores de graça.
O Código em Python:
class HospedeVIP(Hospede): # HospedeVIP herda (E-UM) Hospede def __init__(self, nome, documento, idade,
pontos): # super() chama o construtor do Hospede convencional super().__init__(nome, documento, idade)
self.pontos = pontos # Atributo especifico exclusivo do VIP # Uso: vip = HospedeVIP("Ana", "123", 30,
500) # vip herda 'fazer_check_in()' e a validacao de 'idade' automaticamente!
Analogia do Resort de Olímpia: No resort, temos categorias de quartos. Uma 'Suíte VIP' é um quarto convencional,
mas com uma banheira de hidromassagem e uma varanda a mais. O arquiteto não precisa desenhar toda a planta básica
de quarto do zero (com teto, paredes, fiação, porta). Ele simplesmente herda o projeto do Quarto Comum (relação 'Suíte
é-um Quarto') e acrescenta na planta apenas as especificidades VIPs (a jacuzzi e a varanda). Isso economiza tempo e
centraliza as regras de infraestrutura básica em um único molde principal!
